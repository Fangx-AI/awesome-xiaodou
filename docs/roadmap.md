# 小豆 Skill 建设计划

核心目标是帮用户计划得更好，并提高完成真实任务的机会。用户只需说目标、调整或回报进展；三省和六部负责处理复杂度。人物图帮用户理解部门在哪些时候有用。

| 阶段 | 工作 | 完成条件 | 当前情况 |
| --- | --- | --- | --- |
| 1 · 第一次用 | 首页写清能得到的结果，提供体验入口、粘贴包和技能 ZIP | 第一次打开能选场景、看到下一步、找到续聊方式 | 本轮交付 |
| 2 · 办完一件事 | 工作台从目标到行动记录，支持改时间、遇阻调整、刷新续接 | 完成和遇阻各走一遍，记录保留，复制到小豆时包含目标和下一步 | Chrome 已跑通规划、调整、复制、归档及新目标，390px 宽度无横向溢出 |

| 5 · 信任与反馈 | 区分计划、草稿、本人回报、工具回执。核对超时后的状态，支持分享实际结果 | 测试错误返回无重复执行，反馈表能定位具体版本与场景 | 提示词和反馈表已具备，连接器需真机验证 |

## 主场景

- **朕要减肥**：从今天这一餐或一个习惯开始，忙时改计划，按已有记录做一周复盘。按需使用用户实际菜单、时间及目标。
- **朕要做条视频**：把空泛目标缩成主题和素材，粗剪后记录交付。
- **朕要约朋友**：先对齐时间、地点和预算，再准备邀约草稿。发送前由用户确认。
- **自己写**：把任意目标写成可验证的完成标准，再选一件能动手的事。需要理解自由文本时复制进度到小豆续聊。

网页的建议由预设规则生成，进度存在当前浏览器。小豆端按粘贴的内容继续。技能端的连接器能力需要单独验证。

## 按验证结果推进

### P0：真实用户能把一件事推进下去

1. 对三个预设场景分别准备一条普通问法和一条装载 Skill 后的问法，使用相同输入与约束。记录首轮追问次数、是否给出可执行动作、动作是否符合手头时间。
2. 用同一目标回报一次完成、一次受阻，再修改时间或预算。核对是否接着原进度走，是否给出更小而可完成的动作。
3. 复制进度到一个新对话。核对目标、已做、卡点和下一步是否完整。把模型与 App 版本、日期和脱敏结果放进[试用记录](prompt-quality.md)。
4. 用测试日历与测试收件地址复跑外部操作。至少覆盖撤回授权、操作后超时、内容或收件人变化三种情况，确认重复请求前先查询状态。

### P1：用一周，验证哪些东西值得留下

1. 让试用者从三个主场景中自行选一个。第 1 天记首个动作，第 3 天看卡点，第 7 天看回顾能否说明实际做了什么。按场景统计，并记录未返回或无法确认的情况。
2. 复盘反馈时先看「是否做完一步」和「是否愿意再来」，再看称呼、人物、措辞等喜好。对跟进负担过高的流程，优先减少重复提问和表单字段。
3. 把成功与失败都写成脱敏案例。只有能重复达到目标的做法，才在首页用实际结果说明。

### P2：扩大可用场景并更新传播素材

1. 按用户实际提出的问题选新增玩法。每条至少写清输入、输出、失败时的替代办法，并标注是否需要连接器。
2. 用已经验证的案例制作 README 演示、带编号的两三张分享图和短视频素材。第一帧展示用户说的话，第二帧交付能验证的结果。
3. 发布时同步检查 README、在线体验、短版、整包和 ZIP。保留更新说明和旧版本链接，方便复现。
