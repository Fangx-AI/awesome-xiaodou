# 实测边界与待核实问题

[返回首页](../README.md) · 记录日期：2026-11-24

## 阅读体验记录时要区分

| 看到的证据 | 能说明什么 | 仍不能说明什么 |
| --- | --- | --- |
| 某连接出现在界面中 | 存在入口 | 所有账号都能用、所有动作都能完成 |
| 小豆创建了跟进卡片 | 任务已配置 | 条件到来时一定通知、长期没有漏报 |
| 出现提单或叫车卡片 | 流程走到确认步骤 | 已支付、司机已接单 |
| 作者报告一次成功 | 该作者报告的单次结果 | 本项目复现、普遍成功率 |

## 有来源的使用边界

- **购物支付**：智东西体验中仍需人工核验和支付。[来源](https://www.36kr.com/p/4083578123184773)
- **电话号码**：爱范儿提醒直接输入号码并不是可用的通用拨号方法。应描述商家和事项，由产品识别可处理的服务。[来源](https://www.ifanr.com/1691355)
- **推送体验**：歸藏提到回复冗长及主动内容过密的问题。该反馈针对其体验阶段，不能推定一直未改善。[来源](https://weibo.com/2/detail/5368835221753457)
- **任务时效**：早报、公告和开票场景没有统一的响应速度或漏报率数据。本库不把示例周期写成产品保证。

## 尚待追溯的失败记录

[什么值得买的二次汇总](https://post.smzdm.com/p/aggwp673/) 提及外卖未完成、门店信息不准确、盯价时需手动补商品链接等现象。本次没有定位到相应原始测试视频，因此只保留线索，不能据此断言所有账号均不支持这些能力。

该汇总对第三方生态接入的概括，与[智东西文章](https://www.36kr.com/p/4083578123184773)列出的连接存在表述差异。因此不采用“完全没接入某一体系”这种笼统结论；以具体应用、动作及账号版本记录。
