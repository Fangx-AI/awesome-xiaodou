# 小豆皇帝模拟器 · 首用、续办与传播

**体验承诺。** 用户第一次会话拿到贴合自己情况的结果，第二次可以接着实际进度走。简单事务当场交付，多周计划先问缺失的关键条件，资料够了再排。喜欢皇帝设定的人能展开朝议，只想把事情办好的人照常说话。

| 体验要点 | 在产品里的做法 | 怎样验证 |
| --- | --- | --- |
| 今天就有收获 | 资料够时直接交能用的草稿、安排或清单。一个月的个性化计划若缺资料，先一轮集中问清，沿用用户已经给出的约束 | 冷读后让人说出能拿到什么。首次会话记录必要问了几轮、信息够后是否兑现交付 |
| 计划被打断也能继续 | 用户说「今晚只剩五分钟」时，保留已经写好的第一句，交一个五分钟内能完成的改案 | 用同一条约束变更对照普通小豆和皇帝模拟器，核对是否记住了成果、是否只改受影响项 |
| 有明确的完成感 | 用户反馈「我做了」后，只复述确实做过的事，并给一个下次能接着做的动作。漏一次允许在下一个真实机会继续 | 找到回访的实际原因，是拿回进度、解决新问题，还是因为收到提醒。把主动回访与研究人员邀请回访分开 |
| 别人一眼能学会 | 分享展示「原计划、发生的变动、现在能做的事」。每条带可复现的使用入口。真实案例经同意脱敏后使用 | 让没看过项目的人看完案例，复述改了什么，再观察是否能在 App 自己完成一次 |
| 用户自己决定节奏 | 可以一句话开局、改目标、换称呼、暂停或结案。提醒由用户主动提出并确认；角色细节随问随展开 | 检查用户说今天不做、想休息或不想续办时，是否得到一个轻松清楚的结束 |

把行动和具体情境绑定，来自实施意图研究。用实际成果反馈的设计参考了进度监测研究，以及自我效能与自主支持理论。传播上先展示别人可以照做的有用案例，参考对实用性与分享的研究。研究支持这些设计假设；小豆用户是否更愿意回来，以[实际试用](field-tests/pilot-observer.md)验证。 [实施意图实验](https://sparq.stanford.edu/sites/g/files/sbiybj19021/files/media/file/gollwitzer_brandstatter_1997_-_implementation_intentions_effective_goal_pursuit.pdf) · [目标进度监测荟萃分析](https://pubmed.ncbi.nlm.nih.gov/26479070/) · [自我效能研究](https://pubmed.ncbi.nlm.nih.gov/847061/) · [自我决定理论](https://pubmed.ncbi.nlm.nih.gov/11392867/) · [分享与实用性研究](https://journals.sagepub.com/doi/10.1509/jmr.10.0353)

## 同一个案例怎么讲

**长文开头**用一句能看懂的真实矛盾。示例为「原定练 15 分钟，临时加班只剩 5 分钟」。下一屏给具体改案：「第一句保留，今晚只读一遍，圈一处卡住的地方」。最后再解释门下为什么退回、尚书怎么交办。

**三张图或短视频分镜。** 第一张写用户遇到的变化，第二张呈现回奏与可用结果，第三张给小豆 App 的开局入口。演示图标「流程示例」，真机图附 App 版本与已获得授权的脱敏来源。图上的内容和 README 保持一致。

[五张场景分享图和开场示例](share-cards.md)

**月计划案例给想开始的人。** 用「午饭只能点外卖，四周计划怎么排？」开头。图上从中书先问情况讲到尚书交首周安排。转发时附完整对话，读者能接着复制开局。 [下载月计划分享图](../assets/xiaodou-monthly-plan-share.png) · [打开完整对话](weight-first-week.md)

### 可转发的试用邀请

**给已经能进入小豆 App 的人**

> 原本想练 15 分钟英语，临时加班只剩 5 分钟。我们做了个「小豆皇帝模拟器」，这时会保留写好的第一句，只改今晚剩下的安排。你可以带一件自己原本就想做的事试试，比如开始阅读、练英语，或把一个月的饮食计划排顺。做到第一步、改了计划、卡住了，都欢迎回来报个结果。

[带真实目标试七天](https://github.com/Fangx-AI/awesome-xiaodou/blob/codex/s0-pilot/docs/field-tests/seven-day.md)

**给第一次看到项目、还没开通小豆的人**

> 想请你帮我看三分钟 GitHub 首页。按你平时的方式读，告诉我它是做什么的、你第一下会点哪里。哪句看不明白也请直接说。

[参加首页冷读](https://github.com/Fangx-AI/awesome-xiaodou/blob/codex/s0-pilot/docs/field-tests/cold-read.md)

**两种开头试同一个入口。**

- 场景版「皇上，今天只剩五分钟？照样能把事情往前办一步。」
- 成果版「做过的接着算。计划被打断，小豆只改受影响的那一步。」

两组用同一案例、截图和开局消息，冷读测试交替顺序。读完能说出使用对象、入口和交付物才算理解。渠道访客至少走到一次 App 试用才记入激活，Star 单独记录。获得真实案例后再根据使用结果替换演示。

## 评审时看什么

- 第一轮有没有能直接用的成果，时间和信息条件是否正确。
- 用户回来时能否一行带出已完成和下一步，遇到卡点是否先调整困难所在。
- 用户要休息或结案时是否尊重选择，未请求的提醒和归因不出现在回奏里。
- 分享内容的原案、改案、时间证据、出典和使用入口能否让外部读者验证。
