# 小豆真机首测 · 今晚只剩五分钟

这次检查小豆是否能根据实际变化改计划，以及提醒创建和触发是否有真实回执。大约需要 6–10 分钟。先记录 iOS 或 Android、小豆版本，使用小豆独立 App 的新对话。

## 直接复制做第一轮

**第一条**。把[完整开局消息](../../prompts/xiaodou-pilot-start.txt)原样发到新对话。文件已把首页开局与以下虚构目标放在一起。

```text
朕三天后有英语会议。
今晚有15分钟，想练自我介绍。
开头这句已经写好：Hi, I’m Lin.
先告诉朕今晚怎么练。
```

**第二条**。等小豆回复后，再发：

```text
朕刚收到加班通知，今晚只剩五分钟。
第一句已经写好。只改受影响的部分。
直接告诉朕现在该做什么。
```

**第三条**。若想核对它怎样改案，再发：

```text
展开朝议。
朕想看原安排、为什么退回、
改成什么，以及哪些进度保留。
```

**第四条，用临时任务测试提醒。** 这一步只用小豆自己的提醒，正文使用「御前测试 · 练会议开场」，不涉及其他联系人或现有日程。问小豆：「给我预览一条两分钟后的临时提醒。列清楚时间、时区、内容，等我明确确认。」核对后由测试者在小豆里确认一次。看到创建回执后再等到点，分别记录有没有任务卡、有没有收到系统提醒。若只是出草稿，或账号权限不足，照实记。若创建结果未知，先查任务列表后再决定，避免重复创建。

## 把下面这几项回给观察者

- 系统和 App 版本
- 第一条实际回复，是否给出了一个当下能做的动作
- 改期后的实际回复，是否认得第一句已写好、是否按五分钟排
- 提醒预览、确认后结果、实际触发，三项分别记

可以发脱敏文字或截图。隐藏姓名、通知、账号资料、邀请码、联系人和原有日程。

## 观察者如何做普通小豆对照

先为这名试用者建立一个随机试用编号。对照开新对话，发相同的第一条目标和第二条变化，省略开局消息。交替安排两种尝试的顺序，保持设备、版本、测试素材和连接权限相同。两轮对话尽量不在同一任务上留下共享的可重用记录。若小豆使用了先前记录，在报告里标明。提醒只在单独的真机功能检查中做一次。

逐项记首步是否可执行、追加问题数，以及是否正确保留已完成、只改受影响项、给了可做的一步。先按事实记录，评分时按相同标准核对两组。普通小豆结果也保留。 [观察者记录方法](pilot-observer.md)
