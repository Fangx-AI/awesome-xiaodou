# 小豆试用观察与统计

目标是知道用户能否看懂入口、完成第一件真实的事，以及小豆在条件变化后是否改得对。首批两项验收分别是 12 名冷读者与 100 名外部试用者。真机功能测试的固定材料用于核验能力，由用户自选真实任务的七天试用用于衡量完成。

## 冷读 12 人

给从未看过项目的读者同一个 README 版本，记录入口为仓库根页或 README 直达、设备与浏览器视口。先让对方独立阅读，再依次问四件事：这是什么、在哪里使用、怎样开始、涉及发送或提醒时谁确认。观察对方实际找到入口。四项均答对且找得到入口，记录为冷读通过。保留脱敏原话用于改首页。

## 七天自选任务

1. 记录试用编号、来源渠道、App 版本。用户在独立 App **实际发出**第一条启用消息才算启动。一个人只登记一个编号。
2. 约定一个用户能判断完成的实际动作，例如「练一次会议自我介绍并写下卡点」。个性化计划可以先完成必要立案；记录从开局到首次拿到合格行动的用时和轮次。收到日期与用户明确完成回报后记录。读到建议、助手说准备好了、观察者根据截图猜测，都不计为用户完成。
3. 如果同一件事实际遇到约束变化，记录本次改后的回复。先核对原先已完成的动作，然后查受影响项和新下一步。在同一个人有多次变化的情况下，统计每人的第一次能评分的实际变化。
4. 记录用户第 6–8 天是否主动回来看同一计划。由研究人员催回的单独记为受邀回访。可缺省，仍保留到期启动作为分母。
5. 第 7 天到期后汇总各批次。比较普通小豆与皇帝模式的参与者使用[固定材料](pilot-s0.md)另做对照，保持顺序交替。实际用户、模拟对话和固定材料测试分别登记。

## 保存可复算的结果

在工作区的公开仓库以外保存结构化匿名记录。下方是格式示例；每项评分取值为 `true`、`false` 或在尚不可判断时省略该项。日期用与测试者一致的本地日历。可保留各受试者同意的脱敏证据，统计文件只记录必要字段。

```json
{
  "as_of": "2026-12-08",
  "cold_reads": [
    {
      "id": "P-0001",
      "answers": {"identity": true, "where": true, "how": true, "confirmation": true},
      "found_start": true
    }
  ],
  "trials": [
    {
      "id": "P-0001",
      "channel": "community",
      "started_on": "2026-12-01",
      "first_action": true,
      "finished_on": "2026-12-02",
      "change": {"preserved": true, "affected_only": true, "actionable": true},
      "return": {"day": "2026-12-07", "prompted": false}
    }
  ]
}
```

从项目根目录运行 `python scripts/pilot_measure.py <结构化匿名文件路径>`。报告分冷读、首步、已到期七天队列、改案和主动回访。不同批次使用各自的版本记录；每次报数附日期、样本数和未反馈数。达标数值只能作为推进依据之一，还需核验真机原生动作的回执和触发，并检查对照试用中实际观察到的问题。 [阶段目标](../Outcome-Roadmap-2026.md)
