# 旧待办又提醒，先核对项目状态

项目已经交了，小豆却拿旧文档催你补材料？凤凰网科技作者遇到过这件事。小豆找到了一份还写着缺配图的飞书记录，但作者的项目已完成。 [凤凰网科技实测](https://original.ifeng.com/c/8yLT38Uc7Ug)

## 三省怎么走

1. **中书省定位。** 对齐项目、阶段和旧提醒出处。有同名项目时，先问你指哪一件。
2. **门下省核对。** 旧文档里的待办可能已做完。看最新的交付回执或你明确确认的状态。结案后新增的事项单独核对。
3. **尚书省交待办。** 只列目前确实还要做的事。你要停提醒时，先列出具体哪条和操作预览，再按实际回执回报。

## 在小豆里试

```text
请帮我核对这条旧提醒。先定位同一个项目和阶段，列出旧文档写的待办、各条记录的日期或版本，以及我现在确认的状态。旧文档还写着待办、但我确认同一项目和阶段已经结案时，在当前计划保留完成结果，旧待办归为历史记录。结案后出现明确的新事项时，列出新增的那一项让我决定是否接。判断不出是同一项目、同一阶段或哪条记录有效时，问我一个必要问题。只查看我给的摘录或授权范围。原提醒是否已停止、源文档是否已改，都按实际回执说。要停提醒或改源文档时，先定位具体任务或文件、给我变更预览，再等我确认。权限不足时给手动核对方法。
```

可以先贴一段脱敏的旧提醒，再说「这个项目昨天已经交了，另一阶段还在做」。核对小豆有没有保留已交进度，只处理你点名的阶段。若看不到任务列表，先按名称和触发时间手动核对原提醒。 [小豆使用状态](../docs/compatibility.md)
